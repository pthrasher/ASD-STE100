# Rule 8.1 – Punctuation

> **Rule 8.1** **You can use all standard English punctuation marks but not the semicolon (;).**

Source: [Issue 9, Rule 8.1](../../../issue-9/part-1-writing-rules/section-8-punctuation-and-word-count/rule-8-01.md) gives the full text and the original examples.

## In software text

The profile adds this decision: Rule 8.1 is applicable to text, not to code. A semicolon in a code span or in a code block is part of the code. Do not remove it and do not change it ([Section 10](../section-10-code-in-text/README.md)). A semicolon in the text of a code comment is text, and the rule is applicable to it.

In text, write two sentences. Do not connect them with a semicolon. Semicolons occur frequently in these types of text:

- Commit messages and pull request descriptions: a semicolon connects two changes. Write two sentences. If the two changes are not related, make two commits ([commit messages](../../text-types/commit-messages.md)).
- Error messages and log messages: a semicolon connects the error and the next step of the program. Write the error in one sentence and the next step in a second sentence ([error messages](../../text-types/error-messages.md), [log messages](../../text-types/log-messages.md)).
- Agent instructions: a semicolon connects an instruction and its cause. Write the instruction, then write the cause in a new sentence ([agent instructions](../../text-types/agent-instructions.md)).

## Examples

- [Non-STE] Set `retries` to 0; the default is 3.
- [STE] Set `retries` to 0. The default value is 3.
- [Non-STE] Connection refused; retrying in 5s.
- [STE] The server did not accept the connection. The client tries the connection again in 5 seconds.
- [Non-STE] The cache is now invalidated on write; stale reads should no longer happen.
- [STE] When the service writes a value to the database, it also removes that value from the cache. Thus, the service cannot get an incorrect value from the cache.
- [Non-STE] Don't edit `schema.sql` by hand; it's generated by `make schema`.
- [STE] Do not change `schema.sql` manually. The `make schema` command makes this file.

## Review notes

- A check can find all semicolons. It must first remove code spans, code blocks, URLs, and HTML entities (for example `&nbsp;`). If it does not remove them, it shows correct code as areas to review.
- Do not remove a semicolon from code to make a check show no result. The code then changes, and it can stop operating correctly. An agent that corrects text must not change code spans or code blocks.
- A check cannot find a semicolon that a writer replaced with a comma or a dash. The two parts are then one long sentence, and the problem stays. The reviewer must read each sentence that has a comma or a dash between two clauses.
- When you divide a sentence at a semicolon, the second part frequently has no subject or no verb. Write a full sentence. The reviewer must select the correct structure: two sentences, two list items, or two commits.
- A result of zero semicolons does not show that the text obeys Section 8.
