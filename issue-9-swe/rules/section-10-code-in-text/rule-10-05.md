# Rule 10.5 – Placeholders

> **Rule 10.5** **Write placeholders in one format in all of the text. Tell the reader which value to put in each placeholder.**

Related: [Issue 9, Rule 1.11](../../../issue-9/part-1-writing-rules/section-1-words/rule-1-11.md) (one technical noun for one item) and [Issue 9, Rule 9.4](../../../issue-9/part-1-writing-rules/section-9-writing-practices/rule-9-04.md) (a consistent style). Profile pages: [Rule 1.11](../section-1-words/rule-1-11.md), [Rule 9.4](../section-9-writing-practices/rule-9-04.md). [Rule 10.3](rule-10-03.md) tells you how to write a command in a code block.

## In software text

A placeholder is a part of a command, a path, or a code example that the reader must replace with a value. Frequent formats are `<branch-name>`, `{branch}`, `$BRANCH`, and `YOUR_BRANCH`. Select one format and use it in all of the text. If the project has a style guide, use the format of the style guide. If it has no format, this profile recommends angle brackets and lowercase words with hyphens: `<branch-name>`.

If a text uses more than one format, errors can occur, specially for an agent. In some languages, each format has a different function. In a shell, `$BRANCH` is a variable, `{a,b}` is a list of words, and `<` sends a file to a command. If the text uses one format, an agent can find all of the placeholders and replace them.

A placeholder in the format `$NAME` is dangerous in a shell command. If the reader does not replace it and the variable is not set, the shell replaces it with no text. For example, `rm -rf $BUILD_DIR/*` then deletes the files in the root directory (`/`). With `<build-dir>`, the shell shows an error and does not execute the command.

Tell the reader which value to put in each placeholder. Put a list of the placeholders immediately after the code block, in the same step. For each placeholder, give the value and, if possible, an example.

Tell the reader if the brackets are part of the value. Usually they are not: write “Do not include the angle brackets.” If the value must contain the same characters as the placeholder format, give a full example of the result.

## Examples

- [Non-STE] Clone your fork:

  ```sh
  git clone https://github.com/$USER/{repo}.git
  ```

  (The text uses two formats, and it does not tell the reader the values. In a shell, `$USER` is a variable. Its value can be different from the GitHub user name.)

- [STE] To clone your fork of the repository, execute this command:

  ```sh
  git clone https://github.com/<username>/<repository>.git
  ```

  Replace each placeholder with its value. Do not include the angle brackets.
  - `<username>`: your GitHub user name
  - `<repository>`: the name of your fork, for example `app`

- [Non-STE] Execute this command:

  ```sh
  curl -H "Authorization: Bearer TOKEN" https://api.example.com/v1/me
  ```

  (The reader cannot know that `TOKEN` is a placeholder, or which token to use.)

- [STE] To get the data of your account, execute this command:

  ```sh
  curl -H "Authorization: Bearer <api-token>" https://api.example.com/v1/me
  ```

  Replace `<api-token>` with an API token of your account. You can make this token on the “Tokens” page of your account. Do not include the angle brackets.

- [Non-STE] To change the author of the last commit, run `git commit --amend --author="<name> <email>"`.

  (The reader cannot know which angle brackets to keep. The value of `--author` must have angle brackets around the e-mail address.)

- [STE] To change the author of the last commit, execute this command:

  ```sh
  git commit --amend --author="<name> <<email>>"
  ```

  Replace `<name>` and `<email>` with their values.
  - `<name>`: your full name, for example `Ana Silva`
  - `<email>`: your e-mail address, for example `ana@example.com`

  Keep the outer angle brackets around the e-mail address. They are part of the value. Example of the result: `--author="Ana Silva <ana@example.com>"`

## Review notes

- Examine all of the text, not only one code block. Find each placeholder format that the text uses.
- Find which text is a placeholder and which text is syntax of the code. `$HOME`, `{}` in `find -exec`, `List<String>`, and `{{ .Values.image }}` are code, not placeholders.
- Make sure that the text tells the reader the value of each placeholder, and that this information is correct.
- An example value, for example `my-bucket` or `example.com`, can be a placeholder. If the reader must replace it, the text must tell the reader.
- A mechanical check can find text in code format that is possibly a placeholder, for example `<…>`, `{…}`, `$` and uppercase letters, `YOUR_…`, or `…_HERE`. It can show a text that uses more than one format, and a placeholder that the text near the code block does not refer to. Thus, the value is `suggests`. The check fails in these conditions:
  - It shows code as a possible problem, for example the syntax in the list above.
  - It does not find placeholders in other forms, for example `my-bucket`, `xxx`, or `1.2.3.4`.
  - It cannot tell if the text gives the correct value.
  - An automatic correction that changes `$HOME` to `<home>` makes a correct command incorrect.
