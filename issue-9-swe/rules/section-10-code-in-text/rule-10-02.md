# Rule 10.2 – Word count

> **Rule 10.2** **Count each code span as one word. Do not count the text in a code block.**

Related: This rule extends [Issue 9, Rule 8.6](../../../issue-9/part-1-writing-rules/section-8-punctuation-and-word-count/rule-8-06.md) and the profile page [Rule 8.6](../section-8-punctuation-and-word-count/rule-8-06.md). Rule 8.6 counts alphanumeric identifiers and quoted text as one word.

## In software text

A code span counts as one word. Rule 8.6 counts an alphanumeric identifier or quoted text in the same way. A code span of one character and a code span of 60 characters each count as one word. [Rule 10.1](rule-10-01.md) tells you which text is in code format.

A code block is not part of a sentence. Do not count its text in the sentence before it or after it. Count the sentence that comes before the code block, for example “To install the dependencies, execute this command:”. The colon before a code block has the same effect as the colon before a vertical list in [Rule 8.4](../section-8-punctuation-and-word-count/rule-8-04.md). It shows the end of the sentence.

Use the usual limits with this count: 20 words in a procedural sentence ([Rule 5.1](../section-5-procedural-writing/rule-5-01.md)) and 25 words in a descriptive sentence ([Rule 6.3](../section-6-descriptive-writing/rule-6-03.md)). If a code span is in parentheses, all of the text in the parentheses counts as one word ([Rule 8.5](../section-8-punctuation-and-word-count/rule-8-05.md)).

A long code span is one word, but it can make a sentence not easy to read. This is possible with a full command and its arguments, or with many code spans in one sentence. A reviewer must make a decision about each of these sentences. If the reader must execute the command, put it in a code block ([Rule 10.3](rule-10-03.md)). If a sentence has many code spans, use a vertical list or a table.

The text of a code block is not in the count, but other rules can be applicable to it. For example, comments in a code block are code comments. Refer to [code comments](../../text-types/code-comments.md). In plain text, for example a commit message, code is frequently not in code format. Count each identifier, command, and path as one word, the same as a code span.

## Examples

- [Non-STE] If `--output` is not set, the `export` command writes the report to `stdout` and the progress messages to `stderr`, so you can pipe the report into `jq` without extra flags.

  (Each code span counts as one word. The sentence has 30 words. The limit for a descriptive sentence is 25 words.)

- [STE] If you do not use the `--output` flag, the `export` command writes the report to `stdout`. It writes other messages to `stderr`. Thus, you can send the report directly to `jq`.

  (The three sentences have 16 words, 6 words, and 9 words.)

- [Non-STE] To start the dev stack, run `docker compose up -d db cache && npm run migrate && npm run dev` in the repo root.

  (The code span counts as one word, and the sentence has 11 words. But the code span contains three commands. The reader cannot easily see them.)

- [STE] To start the local environment, execute these commands in the root directory of the repository:

  ```sh
  docker compose up -d db cache
  npm run migrate
  npm run dev
  ```

  (The sentence has 15 words. The code block is not part of the word count.)

## Review notes

- Each code span counts as one word. Its length has no effect on the word count. No number of characters is a correct limit for all texts. Examine each long code span and make a decision: keep it, put it in a code block, or divide the sentence.
- A sentence can be in the word limit and have too many code spans. If the reader cannot easily find each item, use a vertical list or a table.
- Make sure that the writer did not put English words in code format to decrease the word count ([Rule 10.1](rule-10-01.md)).
- In Markdown, a mechanical check can find each code span and each code block between lines of backticks. It can count each code span as one word and ignore each code block. But much software text has no Markdown. Thus, the value is `suggests`. The check fails in these conditions:
  - Plain text, for example a commit message, a log message, or a code comment, frequently has no backticks. The check then counts a command, for example `docker compose up -d`, as four words.
  - The check cannot find the other elements of Rule 8.6, for example quoted text and proper nouns. Thus, the word count can be too high. Refer to [LIMITS.md](../../review/LIMITS.md).
  - A code block that has an indent and no backticks, or a code span that has no second backtick, gives an incorrect count.
  - The check cannot tell if a long code span makes the sentence not clear.
- Do not change a sentence only to decrease the count. A writer or an agent can put words in code format, or remove articles ([Rule 4.2](../section-4-sentences/rule-4-02.md), [Rule 4.5](../section-4-sentences/rule-4-05.md)). Then the text agrees with the check, but it is not STE.
