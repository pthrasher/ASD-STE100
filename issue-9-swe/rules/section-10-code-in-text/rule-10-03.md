# Rule 10.3 – Commands

> **Rule 10.3** **When the reader must execute a command, put the command in a code block after the instruction.**

Related: [Issue 9, Rule 5.1](../../../issue-9/part-1-writing-rules/section-5-procedural-writing/rule-5-01.md) (short sentences), [Issue 9, Rule 5.2](../../../issue-9/part-1-writing-rules/section-5-procedural-writing/rule-5-02.md) (one instruction in each sentence), and [Issue 9, Rule 5.3](../../../issue-9/part-1-writing-rules/section-5-procedural-writing/rule-5-03.md) (the imperative). Profile pages: [Rule 5.1](../section-5-procedural-writing/rule-5-01.md), [Rule 5.2](../section-5-procedural-writing/rule-5-02.md), [Rule 5.3](../section-5-procedural-writing/rule-5-03.md).

## In software text

An instruction to execute a command has two parts. First, a sentence in the imperative tells the reader the action, and has a colon at its end. Then, the code block gives the command. Write “Execute this command:” or “To install the dependencies, execute this command:”. Do not write “run.” Refer to [execute (v)](../../dictionary/verbs.md#execute-v) and [run (v)](../../dictionary/verbs.md#run-v).

The code block contains only the text that the reader executes. A person or an agent frequently copies and executes all of the text in the block. Other text in the block then causes an error.

- Do not put a shell prompt, for example `$`, at the start of a line.
- Do not put the output of the command in the same block. Put the output in a second code block, after a sentence, for example “The command shows this output:”.
- Write the language after the first three backticks, for example `sh` or `powershell`. Then an agent knows which shell to use.

If the reader must examine the result of a command before the next command, put each command in a different step ([Rule 5.2](../section-5-procedural-writing/rule-5-02.md)). A code block can contain more than one command if the reader executes them together as one action.

This rule is applicable when the text gives the command that the reader must execute. If the text only tells the reader which tool or command to use, a code span is sufficient: “Use `grep` to find the errors in the log.” The reader then writes the full command. In descriptive text, a command in a code span is also correct: “The `make lint` command does the lint checks.”

If a command can cause damage to data or to a system, write a caution immediately before the instruction ([Rule 7.2](../section-7-safety-instructions/rule-7-02.md)). Issue 9 uses a caution for a risk of damage to objects. In this profile, data, software, and computer systems are also objects ([Rule 7.1](../section-7-safety-instructions/rule-7-01.md)). If the command can also cause injury or death, write a warning. Refer to [Issue 9, Section 7](../../../issue-9/part-1-writing-rules/section-7-safety-instructions/README.md). [Rule 10.5](rule-10-05.md) tells you how to write placeholders in a command.

## Examples

- [Non-STE] Always run `make lint` before committing.
- [STE] Before you commit your changes, execute this command:

  ```sh
  make lint
  ```

  If the command shows errors, correct them before you commit.

  (An instruction in an agent instruction file, for example `CLAUDE.md`.)

- [Non-STE] Check your Node version:

  ```sh
  $ node --version
  v20.11.1
  ```

  (The block contains a prompt and the output. An agent that executes all of the block also executes `$` and `v20.11.1`.)

- [STE] To show the version of Node.js, execute this command:

  ```sh
  node --version
  ```

  The command must show version 20 or a subsequent version.

- [Non-STE] Run `npm ci`, then `npm test`, and make sure everything is green.
- [STE]
  1. To install the dependencies, execute this command:

     ```sh
     npm ci
     ```

  2. To execute the unit tests, execute this command:

     ```sh
     npm test
     ```

  3. Make sure that all tests pass.

## Review notes

- Find if the reader must execute the command. A command that the text only refers to can stay in a code span.
- Examine each code block for prompts and output. Make sure that each line in the block is text that the reader must execute.
- Make sure that the sentence agrees with the block: “this command” for one command, “these commands” for more than one.
- If possible, execute the commands in a test environment. Make sure that the results agree with the text.
- The value is `suggests`, because a mechanical check can find these possible problems:
  - An imperative sentence with a code span that contains a space, or that starts with a known command name, for example `npm`, `git`, or `make`.
  - A line in a code block that starts with `$ ` or `> `.
  - A code block that does not come after a sentence with a colon at its end.
- The check fails in these conditions:
  - It cannot know if the reader must execute the command, or if the sentence only refers to it.
  - Its list of command names does not contain all command names.
  - A line that starts with `$` can be correct, for example `$env:PATH` in PowerShell.
  - It cannot always find output in a block, because a line of output can be the same as a command.
  - An automatic correction that moves each code span into a code block makes the sentences of descriptive text incorrect.
