# Section 10 – Code in text

This section is new in the profile. It is not part of ASD-STE100, and ASD did not examine it. Software text frequently contains words and code in the same sentence: names of functions, commands, file paths, and values. Issue 9 has no rules for code in text. This section gives these rules.

## In software text

The rules in this section tell you which text to write in code format, how to count code in a sentence, how to write a command that the reader must execute, and how to write placeholders. They also tell you not to use a command, a product name, or an identifier as a verb. Code format helps two types of readers. A person who reads English as a second language can see which words are English words and which words are names from the code. An agent can see which characters it must use or find without a change.

## Rules

| Rule | Statement | Status | Mechanical check |
|---|---|---|---|
| [Rule 10.1](rule-10-01.md) | Use code format for identifiers, commands, file paths, and values that the reader types or sees on the screen. | new | suggests |
| [Rule 10.2](rule-10-02.md) | Count each code span as one word. Do not count the text in a code block. | new | suggests |
| [Rule 10.3](rule-10-03.md) | When the reader must execute a command, put the command in a code block after the instruction. | new | suggests |
| [Rule 10.4](rule-10-04.md) | Do not use a command, a product name, or an identifier as a verb. | new | suggests |
| [Rule 10.5](rule-10-05.md) | Write placeholders in one format in all of the text. Tell the reader which value to put in each placeholder. | new | suggests |
